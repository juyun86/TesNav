# TesNav 手机 App、路线传输与源码参考

## 手机侧做什么

TesNav Android 的高德 SDK 规划路线，并产生实时导航快照。2026-11-06 在手机旧安装版中，反编译发现原路线导出只有 points，没有 steps；车端又缺少该版本预期的 HTTP 路线入口。因此即便手机显示路线、快照正常，也不能认为完整路线进入了 C3 模型。

隔离候选增加原始 SDK 路段、端点、道路类型及动作，经过压缩和 UDP 分片传给车端，绑定 session/revision、快照和确认；车端候选在路线不完整时撤销地图，不静默使用另一条路线。分片的 SHA-256 是完整性检查，不等同网络对端身份认证。

一次停车采集得到 791 点和 24 个 SDK 分段，索引及端点在该样本一致；理想位置离线回放、手机编码与 Python 接收回环通过，不能替代行车定位和模型闭环。导航中切换备选路线时曾发现路线组 ID 和引擎 pathId 不是同一套；手机候选等待匹配后再接受指导，停车试验四次未接受旧指导，但无确认或无回调的超时场景尚未闭环。候选 APK 测试后已回滚旧 APK；路测中未证明候选完整路线实际进入车端。

## 本包源码的边界

`reference/app/` 是 2026-11-07 从 TesNav 本机工作树选取的路线导出、分片、切线相关源码和测试；它基于本地 `c9e541f3551c67893b6d513a0332fa2dc198876d`，包含未提交工作区内容，并非某个已发布提交或手机安装包的精确源码。它只截取相关文件，不能单独构建 APK。上游应用仓库：[juyun86/TesNav](https://github.com/juyun86/TesNav)，历史开发分支 [amap-lane-engine-20261013](https://github.com/juyun86/TesNav/tree/amap-lane-engine-20261013)。

`reference/c3-tesnav-candidate/` 及 `reference/c3-host-candidate/` 是 2026-11-06 离线候选的选取片段，需要配套现有宿主、插件和完整依赖；不能直接安装，也不代表本车部署。`reference/c3-model-baseline/` 是 2026-11-06 启动诊断前的三个基线文件，不能证明现运行状态。参考文件统一为 LF 换行，哈希基于本包中的内容，见 [SHA256.json](./reference/SHA256.json)。坐标转换和导航第三方许可说明随对应文件保留。

历史检查记录：Android 路线相关测试及 Kotlin 编译曾通过，本机 Android/Python 分片回环和路线重放曾通过；这些是当时的结果，本次整理未重新编译、重新运行测试或连接设备。实际 SDK 重规划、无确认恢复、手机到车端的可靠传输及模型按同一路线转弯仍待验证。
