# 导航模型底图比较原型

本地分支 `comma-nav-model-input-20261013`，只提供手动诊断工具，不向 C3 模型或控制链发送截图。
复用现有高德地图 SDK 11.2.100，未增加 SDK、进程、网络服务或自动截图循环。
发布版本没有入口且 Activity 拒绝启动；debug/特会开构建在主地图长按原有调试按钮进入，普通点击保持原行为。

## 厂商提供的能力

高德提供[自定义地图平台](https://lbs.amap.com/api/android-sdk/guide/create-map/custom)：
控制台选择模板，编辑背景、道路和文字，发布后下载 Android `style.data`，
或使用样式 ID。在线加载需要购买专业版；本工程使用官方生成的离线文件。
自定义样式是地图外观配置，不是额外下载一份道路数据，也不等同于模型已接受这种图。
SDK 的[夜间地图](https://lbs.amap.com/api/android-sdk/guide/create-map/set-maptype)可以直接使用，
原型在没有自定义样式时用它生成诊断图；夜间配色不等于官方模型的黑白道路样式。

百度也提供[个性化编辑平台](https://lbs.baidu.com/customv2/help.html)，可配置背景、道路填充/描边/宽度、标签及显隐。
本轮没有增加百度 SDK，避免在已有高德路线链路上增加另一个地图运行实例。

奥维官方确认提供[WEB 瓦片服务](https://www.ovital.com/132277-2/)，
URL 为 `getomap_<type>_<z>_<x>_<y>_<ext>_<time>.png/jpg`；支持地图缓存及对象叠加，
但说明内置地图不支持通过该项服务发布。此接口返回渲染后的图片，不是官方 Protomaps MVT 的道路几何和属性。
其[OSM 导入说明](https://www.ovital.com/133009-2/)支持将 OSM 建筑、道路等矢量数据导入，
数据来源仍为 OSM，不能据此称能直接取得高德/百度底层道路矢量。
奥维可用于离线地图准备、查看和分发；目前没有证据显示它能直接替换模型道路瓦片，故未添加奥维依赖或常驻 PC 服务。

## 原型使用

1. 在已有获授权的安装环境打开工具。可读取当前高德 API 位置与同版本原始路线，
   单次冻结；没有连接导航服务时可以手动填写 GCJ-02 坐标和朝向。
   按原始路线初次投影及前后各 50 米的弦确定路线朝向，不使用旧显示简化线。
   本工具只比较固定样本，不维护行车连续路线进度；环路和重叠道路需要人工选定样本。
2. 工具默认加载本轮生成的内置离线实验样式，无需手填 ID 或放置文件。
   可填高德样式 ID；或将 `style.data`、可选 `style_extra.data` 放在 App
   外部专属文件目录 `navigation-map-style/`。在线和本地都有时，由 SDK 优先在线、失败回退本地。
   外部文件覆盖内置实验样式；两者均不可用时使用夜间模板。所有输出均标为诊断数据。
3. 点击「加载样式并定位」，地图 512×512 **物理像素**，俯仰 0，禁用交互、路况、定位蓝点、文字、室内和建筑。
   用真实屏幕投影测量参考距离并修正 zoom，最多三次；超过 1米/像素±5% 时拒绝保存。
   不直接采用 SDK 的 `scalePerPixel`：本机实测该值约为 1 时，100 米仍可投影为约 131 像素。
   SDK 报告比例另存到 `sdkReportedScaleMetersPerPixel`，用于排查设备差异。
4. 手动「保存对照图片」。SDK 必须报告渲染完整、截图尺寸正确，车辆投影必须在 (256,320)±2像素。
   再用北向 100 米参考点验证真实屏幕比例和朝向，与官方 Mercator 投影误差不得超过 5 像素。
   裁剪中心 256×256 后车辆落在 (128,192)。一项截图请求，5 秒超时；退出时失效，迟到回调不能覆盖新请求。

保存目录为外部专属文件目录 `navigation-map-captures/<时间戳>/`：

- `sdk.png`：未经修改的 SDK 截图，保留原有 Logo。
- `basemap-grey.png`：用于检验底图样式的裁剪灰度图。
- `comparison.png`：叠加 5 像素灰色路线和车辆箭头的对照图。
- `metadata.json`：GCJ-02 位置/朝向、原始路线/版本、实测比例、参考投影误差、截图等待耗时及样式来源/请求状态。

所有样本 `modelCompatible=false`。样式调用只记录 requested/失败，不伪造 SDK 未提供的成功确认。
缺少样式时不将普通/夜间底图阈值化后冒充道路语义图。
图片和位置用于本次比较，保存在 App 专属目录，不上传、不写入模型入口。

## 配色与比较要求

专用样式目标：陆地、水面、绿地等背景黑色；道路填充/描边白色；文字、POI、行政线、建筑、铁路/地铁等不作为道路显示。
路线由工具灰色叠加，不使用路况颜色或高德导航箭头。道路分级宽度及桥梁遮挡、隧道绘制需与官方渲染对比，
单纯把所有道路设白色不能证明一致。

取得样式后，分别采普通交叉口、分叉/匝道和高架上下层的固定样本。
同一原始路线和位姿经 GCJ-02→WGS-84 后在官方渲染器生成参考图，检查位置偏移、比例、
道路分级宽度、桥隧遮挡、遗漏道路、路径箭头和字体残留。当前已有一张真实 SDK 模拟道路截图，

## 本地官方参考图比较

C3 本地仓库已增加 `tools/compare_navigation_map.py`，读取上述导图目录和本地 Protomaps PMTiles。
在仓库根目录配置好 Python 环境后执行（Pillow 由原有 tools 的 matplotlib 依赖提供）：

```powershell
python -m tools.compare_navigation_map "D:\samples\capture" --archive "D:\maps\roads.pmtiles" --output "D:\samples\comparison-new"
```

工具将冻结的位姿与完整路线转换为 WGS-84，保持同一朝向，不重新吸附到另一底图库的道路上。
输出 `official.png`、`absolute-difference.png`、三图并排的 `comparison-sheet.png` 和 `report.json`。
另存不叠加路线的 `reference-basemap.png`（仍保留官方车辆标记）。可用 `--reference-source` 描述底图库来源，
该描述仅记入诊断报告，不作为来源已被程序认证的证明。
报告分别记录完整图片差异和排除路线/车辆标记后的道路灰度误差、白色道路交并比、背景残留。
这些指标受地图源道路几何和栅格绘制差异影响，仅供定位差异，不设置“通过即兼容模型”的阈值。
如果参考瓦片缺失或车辆附近没有道路，退出码为 2 且不计算比较指标，不能把空参考图当作有效对照。
输出目录必须不存在，防止覆盖已有样本。此工具不联网、不连接手机或 C3，也不向模型传图片。
